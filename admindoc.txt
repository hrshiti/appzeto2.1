ROLE:
Act as a senior frontend architect and product engineer.
Analyze the existing frontend of the Appzeto website and design a production-grade Admin Module.
This is a real company internal system, NOT a demo or student project.

==================================================
PHASE 1: FULL FRONTEND ANALYSIS
==================================================

First, analyze the ENTIRE existing frontend:

- Pages
- Routes
- Components
- Navigation
- Forms
- Data flow
- User-facing features

Understand:
- What data is being displayed
- What data can be managed internally
- Which sections need admin control
- Which actions should be restricted

Do NOT modify the existing public frontend during analysis.

==================================================
PHASE 2: ADMIN MODULE ARCHITECTURE
==================================================

Design a separate ADMIN MODULE with proper routing and structure.

Admin module should include:
- Dedicated admin layout
- Sidebar navigation
- Protected routes
- Clean dashboard UI
- Professional internal-tool look

Use modular and scalable architecture.

==================================================
PHASE 3: ROLE-BASED ACCESS CONTROL (VERY IMPORTANT)
==================================================

Implement TWO ROLES:

1️⃣ ADMIN (Full Access)
2️⃣ HR (Limited Access)

--------------------------------------------------
ADMIN ROLE (FULL ACCESS)
--------------------------------------------------

Admin can:
- Access ALL admin routes
- View, create, update, and delete ANY data
- Manage:
  - Website content
  - Services
  - Pages
  - Team members
  - Careers / Jobs
  - Blog / Case studies
  - Contact queries
  - Users (Admin / HR)
  - Settings
  - Permissions

Admin has NO restrictions.

--------------------------------------------------
HR ROLE (LIMITED ACCESS)
--------------------------------------------------

HR can ONLY access HR-related routes.

HR is ALLOWED to:
- Manage job postings (create / update / delete)
- Update hiring status
- View job applications
- Update candidate status
- Edit limited HR-related content (if required)

HR is NOT ALLOWED to:
- Access website core settings
- Modify services or pages
- Manage users or permissions
- Access analytics or admin-only data
- Delete critical data

STRICTLY enforce these restrictions.

==================================================
PHASE 4: ROUTE PLANNING
==================================================

Create a clear route structure such as:

/admin
/admin/dashboard
/admin/content
/admin/services
/admin/careers
/admin/blog
/admin/contact-queries
/admin/settings
/admin/users

/hr
/hr/dashboard
/hr/jobs
/hr/applications
/hr/candidates

Each route must:
- Be protected
- Check user role before rendering
- Redirect unauthorized access properly

==================================================
PHASE 5: UI / UX REQUIREMENTS
==================================================

Admin & HR UI must:
- Look enterprise-grade
- Feel like a real internal dashboard
- Have clean typography
- Proper spacing and hierarchy
- No flashy or unnecessary animations

Use:
- Tables
- Forms
- Modals
- Status badges
- Filters and search where applicable

==================================================
PHASE 6: PERMISSION ENFORCEMENT (STRICT)
==================================================

- Route-level protection
- Component-level protection
- Button/action-level protection

HR should not even SEE admin-only actions.
No hidden hacks — proper permission logic only.

==================================================
PHASE 7: SCALABILITY & CLEAN CODE
==================================================

- Use reusable components
- Centralize role and permission logic
- Make it easy to add new roles in future
- Keep code clean and readable
- Follow best practices

==================================================
FINAL DELIVERABLES
==================================================

Provide:
✔ Admin module plan (routes + access rules)
✔ Role-based access logic
✔ UI structure for admin & HR
✔ Clean, production-ready frontend code
